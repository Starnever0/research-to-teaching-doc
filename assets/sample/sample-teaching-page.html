1从一个大家都会遇到的场景说起

你有没有过这种体验：

用 AI 帮你写代码，绝大多数时候它挺利索 —— 建文件、改函数、跑测试，一路顺下去。但偶尔会卡住：

  • 走到一个关键岔路口，方案 A 和方案 B 各有利弊，它选了一个，然后……越走越歪；
  • 或者盯着同一个报错反反复复改，改了七八遍还在原地打转。

这时候你心里最想要的是什么？

不是"换个更强的 AI 从头再做一遍"—— 那太慢也太贵。你想要的是：有个真正的高手，过来看一眼，说一句"你这个方向不对，应该这样"，然后让它接着干。

Claude Code 的「顾问」功能，本质上就是在做这件事。

2一句话说清它是什么

让正在干活的 AI，在关键时刻能"问"一个更聪明的 AI。 这里有两个角色，我们给它们起个好记的名字 —— 主角 和 军师。

主角 · Executor

执行者｜通常是 Sonnet、Haiku
  • 从头到尾把活干完的那个人
  • 负责动手：读文件、写代码、跑命令
  • 自己判断"这儿是不是卡住了"

军师 · Advisor

顾问｜通常是 Opus
  • 平时不露面，关键时刻才出场
  • 负责动脑：看完现场，给一段建议
  • 不动手，不写最终答案
关键点 军师不动手。它不会调用工具，也不会直接产出给人看的答案。它只出主意，动手的仍然是主角 —— 这个"只出主意"的设定，正是整个设计最巧妙的地方。

3和老办法有什么不同

要真正理解一个新东西，最好的方式是把它和你已经懂的东西放在一起看。我们一圈一圈往外比。

3.1　老办法：老板指挥、员工干活

大多数 AI 系统是这样搭的，很像现实里的公司：老板定战略、拆任务，员工执行。

这种模式的问题是：老板太贵了。哪怕只是"把这个文件夹重命名一下"这种小事，也要经过老板的手，于是最贵的那个人力被摊薄在了无数琐事上。

3.2　顾问的办法：员工自己干，卡住了再问

顾问模式把方向反了过来：让干活的模型独立跑完整趟，只在真正卡住时才抬头问一句。

一句话对比：老办法是"老板全程盯着"，顾问是"员工自己干，难处问专家"。省钱的道理也就在这儿 —— 专家只在少数几个岔路口开口，而不是全程跟着。

3.3　再往外比：还有几种"引入第二个模型"的方式

其实"让两个模型配合"有很多种做法，顾问只是其中一种。它们的区别，全在于让强模型在什么时机出场：

方式强模型什么时候出场打个比方
顾问（Advisor） 任务进行到关键决策点时，按需出场 干活的人旁边坐着个专家，卡住就回头问
子智能体（Subagent） 把一整块独立子任务外包出去时 找外包团队，整件事交给他们做
opusplan 只在"做计划"阶段出场，执行时换回便宜模型 专家先把方案定好，剩下照着方案做
切换模型 /model 之后所有轮次都用它 干脆换个人，后面全程请这位强手上

看懂这张表，你就抓住了核心：顾问的独特之处，是"平时用便宜的，只在刀刃那一刻用贵的"。

💡 延伸小知识：它和"混合专家（MoE）"是一回事吗？ 不是，但可以放在一起理解。MoE 是一个模型内部的机制 —— 模型里有很多"专家子网络"，处理每个问题时只激活其中一小部分；顾问则是两个独立模型之间的协作。一个是"一个人脑子里分工"，一个是"两个人配合干活"。但两者的思路很像：让擅长的人做擅长的事，不要所有力气都平均使。

4实际使用时长什么样

4.1　怎么打开

在 Claude Code 里，有三种方式可以设置军师：

# 最常用：在当前会话里指定 Opus 当顾问
/advisor opus

# 不带参数：弹出一个列表让你挑
/advisor

# 关闭
/advisor off
  • 临时用：输入 /advisor opus，指定完就生效。
  • 想长期默认：在配置文件里写 { "advisorModel": "opus" }。
  • 只给这一次会话用：启动时加参数 claude --advisor opus。

设置好之后，界面会一直显示一行小提示：Advisor Tool (experimental) is on and may use more tokens —— 意思是"顾问已开启，可能会多花一点 token"，提醒你留意成本。

4.2　有一条规定要记住

军师的能力，必须不低于主角。这条规则很直觉 —— 你请顾问，总不能让一个比你还菜的人来指点你吧？所以：

  • Haiku（最便宜）可以请顾问，但不能当顾问；
  • 想给 Opus 当顾问，得是同等或更强的模型（比如另一个 Opus）。

如果你配的顾问比主角还弱，系统会直接拒绝，不会让它"滥竽充数"。

4.3　顾问出场时，你能看到什么

当主角决定请军师时，界面上会显示一行 Advising（正在咨询）。几秒后，这行字会变成下面三种状态之一：

状态含义
Reviewed顾问读完了整个对话，给出了建议。按 Ctrl+O 可以看它到底说了什么
Declined顾问认为"这个我不需要插嘴"，拒绝了。同样可以按 Ctrl+O 看原因
Unavailable调用失败（网络、额度等问题），会显示错误信息

有意思的是：主角会认真听建议，但不会盲从。如果它照着建议做，结果实际测试失败了，或者本地文件的内容和建议矛盾，它会把冲突摆出来，而不是硬着头皮执行。必要时它会再问一次军师，把矛盾解决掉。

这个细节很人性化 —— 就像一个靠谱的员工，尊重专家的意见，但也相信自己的眼睛。

5它背后是怎么运作的

现在讲原理。但放心，我们不上技术细节，只说清"发生了什么"。

5.1　一次"咨询"的完整过程

主角发出求助信号

当它判断"这里得问问"时，就发出一个求助请求。注意：要不要问、什么时候问，是主角自己决定的，不是提前写死的规则。

系统把"现场记录"打包送去

到目前为止的完整对话 —— 主角做过什么、看到过什么、说过什么，全部打包，一起发给军师。

军师在服务端读一遍，给出建议

军师拿到的是一份完整的现场记录，所以它能"站在全局"给意见，而不是只看某个片段。

建议回到主角手里

主角拿着这段建议，接着往下干。

整个过程有个很舒服的特点：它是在一次对话里一口气完成的，不需要来回"你问我答"地跑好几趟。对你来说，体验上就是"顺畅地继续往下走"。

5.2　三个值得品味的细节

细节一：军师看的是"全量现场"，不是只言片语。这一点很重要。如果只把某个片段丢给顾问，它可能因为不知道前因后果而给错建议。给全量，顾问才能真正"有全局观"。

细节二：军师不动手，而且不留思考痕迹。顾问只看、只想、只回一段结论，它不调用任何工具，而且它自己的"思考过程"在返回前会被丢掉，只把结论留下来。这么设计有两个好处：一是省钱（顾问通常只输出几百字，而不是重写整篇答案）；二是兼容性好（不管主角、军师是哪个版本的模型，都能配合）。

细节三：什么时候问，由主角自己判断。没有"每三步必须问一次"这种死规则。主角依据对当前处境的判断来决定 —— 通常在定方案之前、反复报错的时候、以及宣布完成任务之前会问一问。想让它多问或少问，直接在指令里说就行，比如"继续之前先咨询一下顾问"。

6它聪明在哪（设计亮点）

理解了原理，我们再退一步看：这个设计到底妙在哪里？

亮点一：控制权牢牢握在"干活的人"手里

主角掌握着整个任务的上下文、状态、工具，而军师被设计成一个"没有记忆、没有工具、只读一次现场、只回一段话"的角色 —— 像一个纯粹的函数：给它现场，它给你一句建议。这个设定让接入变得极其轻量，几乎不用改已有的系统。

亮点二：把"该不该用强模型"的判断，交给了模型自己

以前，工程师要手工设计"哪一步用便宜模型、哪一步用强模型"，这活儿又麻烦又容易出错。顾问模式索性把这个判断下放给正在干活的模型：它自己最清楚"我这儿是不是真的卡住了"。好处是省心，代价是可预测性下降。

亮点三：省钱逻辑的转变

普通省钱思路是"换个更便宜的模型"。顾问的思路是 —— 模型还是那个便宜模型，但把最贵的那个，只用在刀刃上。

够用的模型 · 承担绝大部分工作
日常执行：便宜模型 关键决策：最强模型（只有少数几次）

用一句话概括这种结构性变化：把 5% 的工作交给最强模型、95% 交给够用的模型，往往比 100% 都交给中等模型更划算。

亮点四：用一点点信息折扣，换回成本和兼容性

"不留思考痕迹、只回结论"这个设计，本质上是在做权衡：拿掉一部分可解释性，换来了更低的成本和更广的兼容性。工程上，这种"聪明的取舍"往往比"什么都想要"更实用。

7什么时候用，什么时候别用

✅ 适合的场景

  • 长任务，且大部分步骤是"体力活"、只有几个关键决定成败的。比如大型代码重构、反复报错的疑难调试、交付前让 AI"自己检查一遍"。
  • 量大又要在意成本的场景。比如批量处理文档、海量数据的初步整理 —— 用最便宜的模型当主角，配一个强顾问，既省钱又不至于太笨。

❌ 不适合的场景

  • 一问一答的短问题。比如"这个单词什么意思"—— 根本没有"规划"可言，叫顾问纯属多余。
  • 每一轮都真需要最强模型的任务。这种情况请直接换主角（用 /model），而不是给弱主角配顾问。

判断口诀："大部分步骤很平常，少数步骤特别关键"—— 就是顾问的主场。

8几个要留心的地方

任何新功能都有边界，顾问也不例外：

  1. 它是"实验性"功能。官方明确标注 experimental，行为、价格、可用性都可能调整，用之前心里有数。
  2. 目前只在 Anthropic 官方渠道能用。在 Amazon Bedrock、Google Cloud 等其他云平台上不提供。
  3. 它确实会多花一点点钱。每次咨询都会按"军师"的价格消耗额度。只是因为问的次数少，通常总账还是更划算。
  4. 偶尔会"静默失效"。比如主模型中途因繁忙被换成另一个模型，而这个新模型不满足"顾问配对"规则时，系统会悄悄地不再叫顾问，且不报错。用它做重要任务时，值得多留意一眼。

9用一句话记住它

让够用的 AI 当主力，把最强的 AI 当成随叫随到的军师 —— 好钢用在刀刃上。 它的思想其实一点都不新，反而非常"人间"：平时让能干的人放手去做，遇到真正过不去的坎，再请高人来指点一句。只不过这一次，被安排上这套分工的，是两个 AI。
