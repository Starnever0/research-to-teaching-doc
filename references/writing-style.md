# 科普教学向写作规范

本文件定义 `research-to-teaching-doc` 生成文档时的语气、结构、句式与排版规范。动笔前通读，写作时逐条对照。

---

## 1. 语气与人称

- **对读者说"你"**：营造面对面对讲的亲切感。例："你有没有过这种体验："
- **客观陈述为主，第一人称克制**：讲原理时用客观语气（"主角会……"），只在表达观点时才用"我认为 / 说白了 / 其实"。
- **不端着、不谄媚**：不用"这个问题非常好""让我为您详细介绍"这类填充语。
- **敢下判断**：可以说"这个设计最巧妙的地方在于……"，而不是中立罗列。

## 2. 开篇三件事

1. **场景开场**：用一个读者大概率经历过的具体困扰切入，不要用"随着 AI 技术的发展……"这类宏大开头。
2. **给出痛点**：明确"没有它会怎样"。
3. **抛出承诺**：一句话告诉读者能获得什么（例："不堆公式、不列数据，只讲清它是什么、为什么这样设计、聪明在哪里"）。

反例（不要这样开头）：
> Claude Code 是 Anthropic 推出的命令行编程助手，其最近新增的 advisor 工具……

正例：
> 你有没有过这种体验：用 AI 帮你写代码，绝大多数时候它挺利索……但偶尔会卡住。

## 3. 比喻系统（全文基石）

- **选定一组贯穿角色**，写进第二节，之后全篇复用：
  - 例：`executor → 主角`、`advisor → 军师`、`orchestrator → 老板`、`subagent → 外包团队`。
- **首次出现时同时给出中英文与俗名**，之后可以只用俗名。
- **一致性高于华丽**：宁可朴素但全文统一，不要处处换比喻。
- **务必校验类比准确性**。写完后自问：这个比方会不会让人产生错误认知？

## 4. 从已知讲未知的"圈层对比法"

讲解"它和老办法有什么不同"时，按圈层由近及远铺开：

1. 第一圈：最主流的做法是什么（读者可能已熟悉）
2. 第二圈：本主题相对它做了什么改变（反转 / 增量 / 取舍）
3. 第三圈：还有哪些" cousins "（相似概念并列成表）
4. 第四圈：一个容易混淆的概念辨析（延伸小知识）

每一圈用**一句话对比**收束，例：
> 老办法是"老板全程盯着"，顾问是"员工自己干，难处问专家"。

## 5. 句式与节奏

- **多短句，少长句**。一句一个意思。
- **善用破折号补充**，但不要滥用。
- **关键结论加粗**，每节 2–4 处即可，不要满篇加粗。
- **善用"注意""其实""说白了""换句话说"**作为转折路标。
- **每讲完一个机制，追问一句"为什么这么设计"**，并给出好处与代价。

## 6. 数字、数据与引用的处理

- **默认不出现** benchmark 分数、百分比、价格表、参考文献。
- 若某个数字确实能一句话点透（例："把 5% 的工作交给最强模型"），可保留，但**不做表格堆砌**。
- **需要"论证"的地方，改用逻辑推演或生活化类比**代替数据。
- 确需交代出处时，只在文末一行带过（"具体以官方文档为准"），不列条目。

## 7. 局限与边界必须写

科普不是软文。必须单设一节说明：

- 它是什么性质（实验性 / 稳定）
- 可用范围限制
- 会带来的代价（成本、时间、可预测性）
- 容易踩的坑

用"要留心的地方""几个要注意的点"作小节名，避免"风险提示"这种冷硬标题。

## 8. 排版规范（Markdown）

- 用 `##` 作正文章节（可配 `###` 作小节）；不要用 `#` 抢标题。
- 章节可用编号（`## 一、` 或 `## 1.` 择一，全篇统一）。
- 表格只用于**对比**（角色对照、几种方式并列），不用于堆数据。
- 代码/命令用围栏代码块，配置片段用行内 `code`。
- 关键比喻 / 金句可用引用块 `>` 突出。
- 全文控制在 **2000–3500 字**（中文），确保 8–12 分钟读完。

## 9. 收尾

结尾给一个**所有人都能记住的一句话总结**，最好呼应开篇的比喻：

> 顾问 = 让够用的 AI 当主力，把最强的 AI 当成随叫随到的军师 —— 好钢用在刀刃上。

再补一句"思想其实很人间"式的升华，让非技术读者也能共情。

## 10. 交付前自检清单

- [ ] 开篇是具体场景，不是宏大背景
- [ ] 有一个贯穿全文的比喻，且前后一致
- [ ] 每讲一个机制都说明了"为什么这样设计"
- [ ] 没有堆砌 benchmark 数字表、公式、参考文献列表
- [ ] 相似概念做了并列对比，类比准确无歧义
- [ ] 有独立的"局限 / 注意"一节
- [ ] 术语首次出现有解释
- [ ] 结尾有一句可记住的总结
- [ ] 全文 2000–3500 字，8–12 分钟可读完
- [ ] 事实（产品名 / 日期 / 版本）已核实，不确定处已标注
